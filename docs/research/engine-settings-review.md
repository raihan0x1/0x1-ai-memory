Fokus perbaikan ada pada tujuan pengiriman data, arti hasil Test, dan apa yang sebenarnya dibatasi oleh budget. ## 1. Tujuan data dan kredensial

**P1 · Ikat pemakaian ulang API key ke provider dan endpoint.** Ada satu `api_key` di SQLite. Saat provider berubah, UI mengganti model dan URL tetapi mempertahankan nilai key yang sedang diketik. Input kosong menghilangkan `api_key` dari request Test maupun Save, sehingga backend mempertahankan key tersimpan, termasuk `env:VAR`, sebelum mencoba env bawaan provider baru. Akibatnya key lama dapat ikut terkirim ke tujuan baru. API mendukung pengosongan key dengan string kosong dan UI saat ini tidak mengirimkannya. Hint env di UI juga selalu menunjuk ke OpenRouter saat key belum dikonfigurasi. [Form Engine](../../ui/src/pages/EnginePage.tsx#L206) · [Field key](../../ui/src/pages/EnginePage.tsx#L440) · [Resolusi key](../../src/config.rs#L234) · [SettingsPatch](../../src/config.rs#L346) · [Header request](../../src/llm.rs#L219)

Gunakan ulang key hanya jika provider dan endpoint efektif tetap sama. Saat tujuan berubah, minta pengguna memilih key baru, referensi env, atau koneksi tanpa key. Batasi env bawaan provider ke endpoint resminya dan minta pilihan eksplisit untuk endpoint kustom. Terapkan aturan yang sama di Test, Save, dan Onboarding yang memakai endpoint tersebut. Uji dua server mock pada tujuan berbeda dan pastikan key lama hanya diterima oleh tujuan asal. Uji juga bahwa pergantian model pada tujuan yang sama tetap bisa memakai key tersimpan. [Onboarding](../../ui/src/pages/OnboardingPage.tsx#L219) · [Settings API](../../src/server.rs#L595) · [Test draf yang sudah ada](../../tests/integration.rs#L443)

**P1 · Cocokkan janji `local_only` dengan tujuan aktual.** Classifier distilasi menganggap semua `provider=ollama` lokal meskipun Base URL bisa diubah dan HTTP client memakainya. Classifier embedding melihat URL. Ollama juga mendukung model cloud, sehingga loopback hanya membuktikan tujuan hop pertama. Ada batas lain yang perlu terlihat di UI. Search lintas proyek tanpa `project_id` masih dapat mengirim teks query ke API embedding saat mode `api` aktif. [Classifier](../../src/config.rs#L270) · [Worker](../../src/distill.rs#L68) · [Embedding](../../src/embed.rs#L113) · [Search API](../../src/server.rs#L308) · [FAQ Ollama](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features)

Klasifikasikan adapter yang memakai HTTP berdasarkan URL terurai dan cek tujuan sebelum dispatch, termasuk kebijakan redirect untuk request `local_only`. Nyatakan bahwa proses lokal harus dipercaya agar jaminan berlaku sampai model. Tunjukkan pula status `Distillation off` dan mode embedding sebagai dua pengaturan berbeda. Hari ini `provider=none` masih bisa digabung dengan `embedding_mode=api`, termasuk menggunakan URL default eksternal ketika Base URL kosong. Uji bahwa proyek `local_only` tak menimbulkan request eksternal di distilasi maupun embedding, lalu cek bahwa UI memberi tahu pemakai bila query global dapat dikirim keluar. ## 2. Test dan budget

**P1 · Beri Test arti yang bisa diandalkan.** `POST /api/engine/test` menggabungkan draf dengan settings tersimpan di memori. Test menggunakan prompt sintetis, memanggil adapter yang sama untuk completion, lalu menerima `Ok` dari adapter tanpa memeriksa isi JSON hasil model. Untuk adapter HTTP, respons sukses berisi JSON tanpa konten usable pun dapat lolos. Distilasi sesungguhnya memanggil parser `ExtractionEnvelope` dan bisa gagal pada model yang lolos Test. Mode `none` langsung sukses tanpa request. Route tetap menulis baris `test` ke ledger dengan biaya `0.0`. Test integrasi yang ada memeriksa forward draf, kompatibilitas body kosong, key tersimpan, dan isolasi settings tersimpan dari draf. [Handler Test](../../src/server.rs#L610) · [Implementasi Test](../../src/llm.rs#L99) · [Parser distilasi](../../src/llm.rs#L516) · [Test integrasi](../../tests/integration.rs#L443)

Gunakan satu panggilan sintetis berukuran kecil untuk menguji schema yang benar-benar dipakai distilasi dan tampilkan hasil bagi draf tersebut. Jika hanya memeriksa koneksi, beri status koneksi dengan cakupan yang jelas. Tampilkan `Distillation disabled` jika provider `none`. Hapus status Test ketika provider, model, URL, atau key berubah. Abaikan respons yang masih merujuk ke draf sebelumnya. Uji dengan mock yang mengembalikan 200 dan JSON kosong, mock dengan ekstraksi valid, serta Test yang selesai setelah model diedit. [Handler UI](../../ui/src/pages/EnginePage.tsx#L252) · [Callout](../../ui/src/pages/EnginePage.tsx#L400) · [Field model dan key](../../ui/src/pages/EnginePage.tsx#L422)

**P1 · Sebut batasnya sebagai ambang berhenti berdasarkan pemakaian tercatat.** Distilasi dan API embedding cek total ledger UTC saat ini sebelum panggilan. Tidak ada reservasi untuk biaya atau token panggilan berikutnya. Request terakhir dapat melewati ambang dan request paralel dapat melihat saldo yang sama. Cek yang gagal membaca summary sekarang bisa tetap melanjutkan panggilan. Test melewati cek itu dan biaya Test selalu tercatat nol, meskipun token Test masuk total. Harga distilasi bisa datang dari `usage.cost` atau estimasi lokal, API embeddings eksternal memakai tarif tetap `$0.02` per juta token, dan `0` pada cap USD menonaktifkan cap tersebut. Gagal parse setelah respons berhasil juga dapat mencatat nol ketika provider sudah memproses request. [Agregasi UTC](../../src/db.rs#L1623) · [Cek distilasi](../../src/distill.rs#L100) · [Cek embedding dan tarif](../../src/embed.rs#L120) · [Biaya distilasi](../../src/llm.rs#L247) · [Harga fallback](../../src/llm.rs#L543) · [Biaya Test](../../src/server.rs#L624)

Pakai `GET /api/summary` untuk menunjukkan pemakaian hari ini, limit aktif, dan status terblokir di dekat input cap. Tampilkan `0 = cap USD off`, sebut reset UTC, teruskan biaya Test yang dilaporkan atau diestimasi, dan jelaskan kemungkinan biaya sebelum klik. Untuk Test berbayar, gunakan cek budget terhadap limit tersimpan atau nyatakan dengan jelas jika produk memang menyediakan pengecualian eksplisit. Jika harus menjanjikan hard cap sebelum panggilan, perlu estimasi konservatif, reservasi atomik lintas jalur, dan batas dari provider untuk tagihan aktual bila tersedia. Uji kondisi sudah mencapai cap, hampir mencapai cap, biaya Test, dan summary gagal dibaca. [Summary API](../../src/server.rs#L274) · [Label UI saat ini](../../ui/src/pages/EnginePage.tsx#L471) · [Usage Accounting OpenRouter](https://openrouter.ai/docs/cookbook/administration/usage-accounting)

**P2 · Jelaskan nasib raw event ketika distilasi dilewati.** `none`, privacy block, cap tercapai, dan kegagalan provider menandai batch consumed (`distilled=1`). Event mentah masih ada sampai aturan retention, tetapi worker berikutnya hanya membaca `distilled=0`. Naikkan limit atau ganti provider akan berlaku bagi pekerjaan baru dan event yang masih pending. Salin perilaku ini ke status budget dan petunjuk recovery. Retensi nominal berlaku pada event yang sudah ditandai, sedangkan event yang belum ditandai bisa tersimpan sampai dua kali setting. Uji bahwa perubahan cap setelah ada batch yang diblokir sesuai dengan pesan UI. ## 3. Embeddings dan aktivasi pengaturan

**P1 · Perbaiki preset Gemini embedding dan cegah pencampuran vektor.** Engine dan fallback backend Gemini masih menyebut `text-embedding-004`. Google sudah mematikannya pada 14 Januari 2026 dan sekarang mendokumentasikan `gemini-embedding-2`. Penggantian default perlu menguji response shape dan dimensi aktual terhadap schema SQLite 384 dimensi. Di source saat ini satu indeks cosine menyimpan vektor tanpa identitas model. Sweep hanya mengisi memori yang belum punya vektor, sehingga penggantian backend/model bisa mencampur vektor lama dan baru dalam retrieval. Google juga secara eksplisit mewajibkan re-embed ketika pindah dari Embedding 001 ke Embedding 2. [Hint UI](../../ui/src/pages/EnginePage.tsx#L532) · [Adapter Gemini](../../src/embed.rs#L211) · [Schema vektor](../../src/db.rs#L148) · [Backfill](../../src/db.rs#L1514) · [Shutdown Google](https://aistudio.google.com/docs/changelog#01-14-2026) · [Migrasi Google](https://aistudio.google.com/docs/embeddings#migration)

Tampilkan `Local ONNX` dan `FTS5` sebagai jalur langsung. Jadikan API embedding pengaturan lanjutan, tampilkan tujuan dan model efektif, serta beri status warm-up, kegagalan atau fallback FTS5. Saat model berubah, gunakan FTS5 sampai indeks yang cocok tersedia. Backfill eksternal untuk memori lama perlu persetujuan yang menjelaskan tujuan data. Uji transisi model dengan data lama dan baru, hasil search FTS5 saat berganti, serta larangan backfill eksternal pada proyek `local_only`. Google merekomendasikan 768, 1536, atau 3072 dimensi untuk modelnya, sehingga kualitas retrieval pada 384 perlu diuji dengan contoh proyek sebelum mengiklankannya. [Status dan fallback](../../src/embed.rs#L86) · [API Summary](../../src/server.rs#L274) · [Sweep embedding](../../src/distill.rs#L255) · [Dimensi Google](https://aistudio.google.com/docs/embeddings#control-embedding-size)

**P2 · Perjelas draf, Save, dan status yang sedang aktif.** Engine menyimpan input di komponen yang dilepas ketika pindah tab. `Retry` untuk error generik memanggil load settings dan mengisi ulang field yang sudah diedit. Saat GET settings gagal, UI bisa keluar dari `loading` dengan field default dan Save aktif. Tombol Test, Save, dan field juga bisa saling mendahului, sehingga hasil dapat menempel pada nilai yang lebih baru. Gunakan baseline settings yang berhasil dimuat, indikator perubahan, satu aksi untuk membuang draf, dan simpan perubahan saja. Pertahankan draf saat gagal dan ketika pindah tab di sesi UI yang sama. Simpan input key hanya di memori. Uji pengambilan awal gagal, Save gagal, perpindahan tab, dan respons terlambat. [State dan load](../../ui/src/pages/EnginePage.tsx#L111) · [Retry dan tombol](../../ui/src/pages/EnginePage.tsx#L367) · [Mount Engine](../../ui/src/App.tsx#L598) · [State komponen React](https://react.dev/learn/preserving-and-resetting-state)

Setelah Save, tampilkan kapan pengaturan berpengaruh. Provider dan budget dibaca ketika batch dimulai, briefing dibaca pada `SessionStart` berikutnya, idle dan retention pada sweep worker, dan ONNX dimuat asinkron. Batch yang sudah mulai dapat menuntaskan kerja dengan snapshot lama. Toggle cek update otomatis dibaca ketika pemeriksaan berikutnya berjalan. Auto-Start mengatur login OS dan terpisah dari Save Engine. Kasus daemon perlu peluncuran ulang adalah ketika pengguna mengubah environment proses dari luar, atau perlu mencoba ulang ONNX yang masuk state `Failed` pada implementasi sekarang. Untuk perubahan rutin, tampilkan `Applied for new work` dan pakai status runtime dari summary. Uji daemon dengan PID sama saat memverifikasi perubahan rutin di instance uji. ## Urutan pengerjaan

1. Lindungi reuse key dan pengiriman `local_only` di backend. Perbaiki label `no fallback`, `Zero-LLM`, status tujuan, dan informasi budget di UI pada perubahan yang sama.
2. Buat Test draf menilai kontrak yang dijanjikan, catat biaya, dan pertahankan konteks draf melalui Save, error, dan navigasi. Pakai data summary yang sudah ada untuk status aktif serta budget UTC. Perjelas akibat budget block pada raw event.
3. Pertahankan satu halaman Engine. Urutkan dari status pemakaian dan provider aktif, form distilasi, lalu ledger. Kelompokkan pengaturan search dan briefing. Tempatkan retensi, interval idle, API embeddings, dan kontrol daemon di bagian lanjutan. API embeddings memerlukan preset terverifikasi dan kebijakan indeks saat model berubah.

Validasi usulan dengan provider mock, SQLite sementara, dan contoh memori yang mewakili penggunaan nyata. Provider eksternal belum dihubungi untuk review ini. Save, Auto-Start, dan Stop pada daemon aktif tidak dijalankan.
